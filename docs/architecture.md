# 架构设计

## 总览

longcache 是一个**超长上下文 MoE 推理引擎与 KV Cache 智能管理平台**，围绕
DeepSeek V4.1-Flash 的三大核心创新工程化：

1. **Causal-Encoder-Decoder（CED）非对称结构** —— prefill 激活 8B、decode 激活 16B；
2. **极致 KV Cache 压缩** —— 每 token 仅 890 字节，1M 上下文缓存 < 1GB；
3. **配套基础设施** —— DeepSelect 稀疏注意力 TopK、DeepJIT JIT 编译缓存、deepseek-recipe 协议转换。

## 分层

```
┌──────────────────────────────────────────────┐
│  CLI / Python SDK / REST (OpenAI 兼容)       │  入口层
├──────────────────────────────────────────────┤
│  serving (FastAPI) · protocol (转换/SSE)     │  接入层
├──────────────────────────────────────────────┤
│  engine (CED · 分块 · 流式 · 投机)           │  推理层
├──────────────────────────────────────────────┤
│  sparse (TopK · 模式 · 索引)                 │  注意力层
├──────────────────────────────────────────────┤
│  kv (预算 · 量化 · 压缩 · 驱逐)              │  缓存层
├──────────────────────────────────────────────┤
│  jit (kernel 缓存 · CUDA/昇腾)               │  运行时层
├──────────────────────────────────────────────┤
│  config · core · models (模型卡)             │  基础层
└──────────────────────────────────────────────┘
```

## 数据流

1. 请求进入 serving/protocol，转换为内部 messages；
2. engine 对提示做 CED 编码（分块 prefill）；
3. 编码过程 KV 写入 kv 管理器（量化 + 压缩 + 驱逐）；
4. sparse 对长上下文做 TopK 稀疏注意力选择；
5. decode 自回归生成（可选投机解码、流式输出）；
6. jit 对算子编译产物做缓存，加速重复计算。
